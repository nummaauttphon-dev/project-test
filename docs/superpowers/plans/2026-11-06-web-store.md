# เว็บร้านค้าทดสอบไอเดีย Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** สร้างเว็บขายสินค้าที่รับเงินผ่าน PromptPay พร้อมแนบสลิป และมีหลังบ้านสำหรับตรวจสลิปและจัดส่ง

**Architecture:** Next.js App Router ทำงานฝั่ง server ทั้งหมดผ่าน Server Actions ส่วน PostgreSQL ของ Supabase ดูแลออเดอร์และสต็อกด้วยฟังก์ชันใน transaction และ browser อ่านได้เฉพาะสินค้าที่เปิดขาย

**Tech Stack:** Next.js 16, React 19, TypeScript, Tailwind CSS 4, Supabase (`@supabase/supabase-js`, `@supabase/ssr`, CLI), Zod 4, Vitest, Playwright, axe

**Spec:** `docs/superpowers/specs/2026-11-06-web-store-design.md`

## Global Constraints

- สื่อสารกับผู้ใช้ปลายทางเป็นภาษาไทย ส่วนโค้ดและชื่อไฟล์เป็นภาษาอังกฤษ
- เงินทุกจำนวนเป็นจำนวนเต็มหน่วยสตางค์ และใช้ `formatBaht` ตอนแสดงผลเท่านั้น
- ทุก mutation ผ่าน Server Action หรือ cron ที่ตรวจ secret และใช้ `ActionResult<T>` เมื่อเป็น Server Action
- ไฟล์ที่ใช้ secret key ต้องมี `import "server-only"`
- ห้ามบันทึก token, ที่อยู่, เบอร์โทร หรือเนื้อหาสลิปลง log
- ไม่ใช้ `any` ใน TypeScript และเปิด `strict`
- สลิปรับเฉพาะ JPEG, PNG, WebP ไม่เกิน 4 MB (4,194,304 ไบต์)
- จำกัดสั่งซื้อ 10 ครั้งต่อชั่วโมงต่อ IP, 10 ชิ้นต่อรายการ และแนบสลิป 10 ครั้งต่อชั่วโมงต่อออเดอร์
- ค่าเริ่มต้นร้าน: ค่าส่ง 50 บาท (5,000 สตางค์) และเวลาแนบสลิป 24 ชั่วโมง (1,440 นาที)
- ลบไฟล์สลิป 90 วันหลังออเดอร์เป็น `shipped`, `cancelled` หรือ `expired`
- เป้าหมาย accessibility คือ WCAG 2.1 AA
- ใช้ `proxy.ts` (ไม่ใช่ `middleware.ts`) และใช้ `getClaims()` ในการตรวจตัวตนฝั่ง server ห้ามเชื่อ `getSession()`
- ใช้ `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` และ `SUPABASE_SECRET_KEY` ถ้า CLI ของเวอร์ชันที่ล็อกไว้ให้ชื่ออื่น ให้ map ใน `scripts/test-env.mjs`
- ห้าม deploy, รัน migration กับโปรเจกต์จริง, สมัครแพ็กเกจเสียเงิน หรือ push ถ้าเจ้าของโปรเจกต์ยังไม่อนุญาตในขั้นนั้น

## Review Focus

ทุกข้อมี test อยู่ใน Task ที่ระบุ

1. **ตะกร้าใน `localStorage` เสียหรือเก่า** เช่น JSON พัง หรือมีสินค้าที่ถูกซ่อน: หน้าเว็บต้องไม่พัง และแจ้งรายการที่เอาออก (Task 7)

3. **ไฟล์จาก iPhone เป็น HEIC หรือเปลี่ยนนามสกุลหลอก:** ต้องปฏิเสธด้วยข้อความที่บอกวิธีแก้ (Task 2 และ 9)
4. **ยกเลิกหรือกดซ้ำจนคืนสต็อกซ้ำ:** สต็อกต้องคืนครั้งเดียวเท่านั้น (Task 5)
5. **Session แอดมินหมดอายุระหว่างทำงาน:** ต้องไม่เปลี่ยนข้อมูล และพากลับไป login (Task 10)

## ส่วนที่เพิ่มจาก spec

เพิ่มระหว่างวางแผน และต้องได้รับการอนุมัติพร้อมแผนนี้
